# Scout Finance — אפיון מוכנות לפרסום

## מטרת המסמך

להביא את האתר הסטטי הדו־לשוני למצב פרסום אמין, נגיש, מהיר וניתן לתחזוקה, בלי לשנות את זהות המותג ובלי להמציא תוכן, נתונים או נכסים חזותיים.

## היקף הבדיקה שבוצעה

הבדיקה כיסתה את `build_site.py`, כל 35 קובצי ה־HTML, קובצי ה־CSS וה־JavaScript, מפת האתר, `robots.txt`, מסלולי השפה, הקישורים הפנימיים וטפסי יצירת הקשר.

זוהי בדיקת מוכנות מבוססת קוד, לא ביקורת חזותית מלאה. סביבת הדפדפן המובנית וסביבת Chrome לא היו זמינות ולכן לא נלכדו צילומי מסך ולא אומתו בפועל פריסה, מיקוד מקלדת, תפריטים, שליחת טופס, ביצועי רשת או תצוגה ברוחבים שונים.

## תמונת מצב

האתר אינו מוכן עדיין לפרסום ייצור. הבסיס טוב: קיימים 34 עמודי תוכן דו־לשוניים, אין קישורים פנימיים שבורים, לכל עמוד תוכן יש `h1` יחיד, כותרת ייחודית ותיאור ייחודי, והמשקל הכולל של קובצי ה־HTML קטן. ה־CSS כולל התאמות מובייל והעדפת `prefers-reduced-motion`.

ארבעת חסמי ההשקה הם:

1. הלוגו נטען 68 פעמים מדומיין חיצוני (`scoutwebsite.pages.dev`) במקום מנכס מקומי ומאושר.
2. הטפסים תלויים ב־Netlify Forms, אך ה־README מציג גם יעדי אירוח שבהם הטופס לא יעבוד ללא backend חלופי.
3. עמודי "תובנות" מציגים בפומבי טקסט שמכריז על תוכן עתידי ועל היעדר מאמרים; הם מופיעים בניווט וב־sitemap.
4. מדיניות הפרטיות והצהרת הנגישות מנוסחות כהצהרות כלליות ולא כוללות את הפרטים והתיקוף הנדרשים לפני פרסום.

## ממצאים מרכזיים

### P0 — חייב לפני פרסום

- לבחור Netlify כיעד הפרסום הראשוני או להחליף את מנגנון הטפסים. ההמלצה היא Netlify, מפני שהטפסים כבר מסומנים ב־`data-netlify`.
- להחליף את הלוגו החיצוני בקובץ מקור מאושר בתוך `assets/` ולהוסיף favicon ותמונת שיתוף.
- להסיר את "תובנות" מהניווט ומה־sitemap עד שיש לפחות שני פריטי תוכן אמיתיים; המסלול יכול להישאר עם `noindex,follow`.
- לקבל אישור בעל העסק לכל הטענות העובדתיות: שנות ניסיון, שנת הקמה, מדינות פעילות, תארים ותפקידים, וכן לניסוחי SOX/JSOX/ISOX.
- לקבל בדיקה משפטית למדיניות הפרטיות, הסכמה בטופס, שמירת לידים וספק עיבוד הטופס.
- לבצע בדיקת נגישות אמיתית לפני שהצהרת הנגישות מתארת ניווט מקלדת, מצבי מיקוד וניגודיות כעובדות.
- לקשר `label` ו־`input` בעשרת שדות הטופס שאינם מקושרים כיום באמצעות `for`/`id`.
- להוסיף מסכי הצלחה וכשל ממותגים לטופס ולבדוק שליחה אמיתית בסביבת staging.

### P1 — איכות, נגישות ואמון

- להוסיף קישור דילוג לתוכן, `aria-current` בניווט, `aria-expanded` תקין לתפריט השירותים, סגירה ב־Escape וניהול מיקוד בתפריט המובייל.
- להוסיף `:focus-visible` ברור לכל הקישורים והכפתורים. להשתמש ב־`--blue2: #1769c2` לקו המיקוד.
- להחליף צבעי טקסט חלשים (`#8392a3`, `#7c8b9a`, `#7b8a99`) ב־`--slate: #5e6d7e`. היחסים הנוכחיים על לבן הם 3.18–3.54:1, בעוד `--slate` מספק 5.30:1.
- לתרגם לעברית את `Menu`, `Primary navigation`, `home`, `Email`, `Phone`, `Website`, ואת כתובת המיקום; לסמן מספר טלפון ודוא״ל עם `dir="ltr"` בתוך עמודי RTL.
- להסיר ניסוחים פנימיים ולא־שיווקיים כגון "לפי נתוני המשרד", "מצוין באתר", "ה־firm states" ו"ללא מאמר דמה".
- להסיר חצים טקסטואליים מכפתורים וקישורים במקום לנהל חצים הפוכים בין RTL ל־LTR.

### P1 — SEO ושיתוף

- להוסיף לכל עמוד `og:url`, `og:image`, Twitter Card, favicon, `hreflang="x-default"` ונתוני JSON-LD מתאימים (`Organization`, `ProfessionalService`, `BreadcrumbList`, ו־`FAQPage` רק בעמוד ה־FAQ).
- להפוך את `/` מהפניית JavaScript לעמוד או הפניית שרת. ברירת המחדל המומלצת היא `/he/` עבור דומיין ישראלי, עם קישור שפה בולט לאנגלית.
- להוסיף עמוד 404 דו־לשוני ולוודא שהוא מחזיר סטטוס 404 בפלטפורמת האירוח.
- להשאיר canonical על `https://www.scout-finance.co.il` רק אם זהו דומיין הייצור הסופי.

### P1 — ביצועים ואבטחה

- לארח מקומית את Heebo ו־Inter כקובצי WOFF2 משתנים, ולטעון בכל שפה רק את המשפחה הנחוצה.
- להוסיף cache ארוך לנכסים בעלי שם גרסה, cache קצר ל־HTML, דחיסת Brotli/Gzip וכותרות אבטחה.
- להסיר את סקריפט ההפניה inline בעמוד הראשי כדי לאפשר CSP שאינו כולל `unsafe-inline`.
- להוסיף בדיקות אוטומטיות לקישורים, מטא־נתונים, תלות בנכסים חיצוניים, נגישות בסיסית ורספונסיביות.

## דרישות עיצוב מחייבות

הפלטה נשמרת ללא צבעי מותג חדשים:

- Navy: `#071b33`
- Blue: `#0b4f9c`
- Accent/focus: `#1769c2`
- Ink: `#122337`
- Slate: `#5e6d7e`
- Line: `#dbe3ec`
- Soft background: `#f4f7fa`
- White: `#ffffff`

יש לשמור על האופי הקיים: רקע בהיר, טיפוגרפיה מרווחת, כרטיס navy יחיד באזור ה־hero, קווים דקים, פינות 10/14/18/26 פיקסלים והיררכיה מאופקת. אין להוסיף גרדיאנטים, צבעי הדגשה, איורים או תמונות מלאי ללא מקור מאושר. אם מתקבלים צילום הנהלה או נכסי מותג, יש לשלב רק קבצים מקוריים באיכות פרסום ובחיתוך שנבדק בכל breakpoint.

## מסלולי משתמש שיש לאמת חזותית

1. עברית: `/he/` → פתיחת שירותים → עמוד שירות → `/he/contact/` → הצלחה.
2. אנגלית: `/en/` → עמוד שירות → `/en/contact/` → הצלחה.
3. מובייל: תפריט → שירותים → החלפת שפה → חזרה לאותו עמוד בשפה המקבילה.
4. מקלדת: דילוג לתוכן → ניווט → dropdown → FAQ → טופס → הודעת הצלחה/כשל.
5. שגיאה: URL לא קיים → 404 דו־לשוני → חזרה לבית או ליצירת קשר.

## קריטריוני קבלה לפרסום

- אין נכסי מותג חיצוניים, קישורים פנימיים שבורים או עמודי placeholder ב־sitemap.
- טופס עברי וטופס אנגלי נשלחים ב־staging, נשמרים אצל הספק הנבחר ומפנים לעמוד הצלחה ממותג.
- אין ממצאי Axe קריטיים/רציניים במסלולי הליבה; הניווט והטופס ניתנים להשלמה במקלדת בלבד.
- אין גלילה אופקית ב־320, 375, 768, 1024 ו־1440 פיקסלים ובזום 200%.
- Lighthouse ב־staging: Performance לפחות 90, Accessibility לפחות 95, Best Practices לפחות 95, SEO לפחות 95, במובייל ובדסקטופ.
- כל טענה עסקית, משפטית ונגישותית מסומנת כמאושרת במסמך sign-off.
- DNS, HTTPS, canonical, sitemap, robots, 404 וכותרות אבטחה נבדקו על דומיין הייצור.
